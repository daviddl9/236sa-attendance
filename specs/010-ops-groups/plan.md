## Summary

Add hand-built group membership management (view/add/remove members, create-and-add people) to the existing Groups feature, and add a CLI `seed-groups` command that creates the unit's eight ops groups (RnS, FDC/BOC, BCS, CSS, PSO, A/B/HQ Bty) from the roster Excel using confirmed membership rules, idempotently.

## Phase 0 — Research (findings)

### Roster structure (from the actual file, password `yeoec`)

Rows: 431 people. Columns (0-indexed): `[1]` NRIC last 5, `[2]` Rank, `[3]` Full Name, `[4]` admin number, `[5]` Position Description, `[6]` Unit, `[7]` Sub-Unit 1, `[8]` Sub-Unit 2, `[9]` vocation, `[10]` D.O.B.

### Confirmed seed rules (per unit owner)

| Group | Rule | n |
|---|---|---|
| RnS | Sub-Unit 1 = `BN RECCE & SURVEY TM` | 8 |
| FDC/BOC | Sub-Unit 1 = `FIRE DIRECTION CEN` | 11 |
| BCS | Sub-Unit 2 = `MEDICAL PL` | 16 |
| CSS | S1 CELL (sub1=S1 BR & sub2=S1 CELL) + MT PL + MEDICAL PL + HQ COMBAT TRAIN + posdesc=S4/OC HQ + (sub2=BTY HQ & posdesc=BSM) | 76 |
| PSO | rank ≥ 1SG (rank order map) | 40 |
| A Bty | Sub-Unit 1 = `FIELD ARTY BTY A` | 90 |
| B Bty | Sub-Unit 1 = `FIELD ARTY BTY B` | 89 |
| HQ Bty | Sub-Unit 1 = `HQ BTY` | 139 |

### Matching strategy

- **Authoritative key**: NRIC last 5 (`user.nric_last5`, uppercase-normalized).
- **Tie-breaker/confirmation**: exact full-name match (`upper(full_name) = upper($1)`).
- Query verified users (`verified = true`) by nric_last5; if multiple matches, prefer exact-name match; if still ambiguous, report skipped.
- Rows matched to no user are skipped and reported (count per group).

### Idempotence & non-destructiveness

- Group creation: `INSERT ... ON CONFLICT DO NOTHING` on the creator-name unique index; query existing groups by `created_by` (the CLI creates as a configured admin user) to reuse.
- Member insert: `INSERT INTO participant_group_member ... ON CONFLICT DO NOTHING` — only ever adds.

## Phase 1 — Design

### Backend API (all Tier 3, `RequireUnitCommander`)

```
PUT    /api/groups/{id}/members      body: { "memberIds": ["<user-id>", ...] }
                                      → replace the group's full member list
                                      → 200 { group, memberCount }
DELETE /api/groups/{id}/members/{userId}
                                      → remove one member
                                      → 204; 404 if group missing
                                      → removing a non-member is a no-op (204)
```

`GET /api/groups/{id}` (existing) is extended to return member **details** alongside IDs:

```json
{
  "id": "...", "name": "CSS", "createdBy": "...", "createdAt": "...", "updatedAt": "...",
  "memberCount": 76,
  "members": [
    { "userId": "...", "fullName": "D DAVID LIVINGSTON", "rank": "CPT", "battery": "HQ" },
    ...
  ]
}
```

(new `models.GroupMember{UserID, FullName, Rank, Battery}` struct)

### Service layer (`groups.Service`)

- `SetMembers(ctx, groupID string, userIDs []string) (MemberCount, error)` — in one transaction: validate group exists (else `ErrNotFound`), delete all existing members, insert the new list (dedup), return new count.
- `RemoveMember(ctx, groupID, userID string) error` — delete where group_id+user_id; no error if row absent; `ErrNotFound` if the group itself doesn't exist (checked first).
- `Get` already returns member IDs; extend to also return member detail rows via a JOIN on `"user"` (full_name, rank, battery).

### Seed CLI (`backend/cmd/seed-groups`)

```
FLAGS:
  -file <path>       roster Excel path (required)
  -password <pwd>    Excel password (required)
  -created-by <id>   admin user id owning the seeded groups (required)
  -db-url <dsn>      postgres DSN (default: env DATABASE_URL)

BEHAVIOR:
  1. Open Excel with excelize (password), read the "236 SA" sheet.
  2. For each of the 8 rule definitions, collect matching rows.
  3. Resolve each row to a user: by nric_last5 (+ name tiebreak) among verified users.
  4. Batch-insert groups (reuse existing name) and members (ON CONFLICT DO NOTHING).
  5. Print a summary: per-group created/reused, members added, and unmatched rows.
```

Reuses `findDataSheet`, `cellValue`, `normalizeNRICLast5` from the handlers package (extract shared helpers if needed) or duplicates the small amount of parsing inline — prefer extracted shared helpers to stay DRY.

### Frontend — Groups page

- **Member dialog**: click a group card → `getGroup(id)` → list members (name · rank · battery) with a per-row delete button → `deleteGroupMember(id, userId)`, refetch.
- **Add members**: "Add people" button → dialog with a search box (debounced `listUsers({ search })`), multi-select via checkboxes, "Add selected" → `setGroupMembers(id, allCurrentMemberIds + newIds)`. Also a **"+ New person"** affordance that opens the existing `AddUserDialog` and, on success, adds the created user to the current group.
- Excel-create flow and start-session flow remain unchanged.

### api-client additions

- `getGroupMembers` handled by extending `getGroup` response; add `setGroupMembers(id, memberIds)`, `deleteGroupMember(id, userId)`, and updated types `GroupMember`, `GroupResponse` (`members: GroupMember[]`).
